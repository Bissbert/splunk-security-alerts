## Critical Alert Response Procedures

### 1. Unauthorized SSH Access from Unknown IPs

**Alert Name:** `Unauthorized SSH Access from Unknown IPs`

#### Immediate Actions (0-5 minutes)
```bash
# 1. Verify the alert
splunk search "index=* source="/var/log/secure*" src_ip=<SUSPICIOUS_IP> | head 20"

# 2. Check if IP is truly unauthorized
grep <SUSPICIOUS_IP> /opt/splunk/etc/apps/security_alerts/lookups/authorized_ips.csv

# 3. Identify affected systems
splunk search "src_ip=<SUSPICIOUS_IP> | stats values(host) as affected_hosts"
```

#### Containment (5-15 minutes)
1. **Block the IP immediately**
   ```bash
   # Add to firewall blocklist
   iptables -A INPUT -s <SUSPICIOUS_IP> -j DROP

   # Update Splunk lookup
   echo "<SUSPICIOUS_IP>,false,blocked,$(date +%Y-%m-%d)" >> blocked_ips.csv
   ```

2. **Disable compromised accounts**
   ```bash
   # Disable the account
   usermod -L <USERNAME>

   # Force logout
   pkill -KILL -u <USERNAME>
   ```

3. **Isolate affected systems**
   - Remove from network if critical data at risk
   - Enable enhanced logging

#### Investigation
- Review authentication logs for the past 7 days
- Check for persistence mechanisms
- Analyze commands executed during the session
- Look for lateral movement attempts

---

### 2. Data Exfiltration Attempt

**Alert Name:** `Data Exfiltration Attempt`

#### Immediate Actions (0-5 minutes)
```bash
# 1. Identify the scope
splunk search "index=* src_ip=<SOURCE_IP> bytes_out>104857600 | stats sum(bytes_out) as total_bytes by dest_ip"

# 2. Check destination reputation
curl -X POST https://api.virustotal.com/v3/ip-addresses/<DEST_IP> -H "x-apikey: <API_KEY>"

# 3. Identify data types potentially exposed
splunk search "src_ip=<SOURCE_IP> | transaction maxspan=1h | table _time, user, file_path, operation"
```

#### Containment (5-15 minutes)
1. **Network isolation**
   ```bash
   # Block outbound traffic from source
   iptables -A OUTPUT -s <SOURCE_IP> -j DROP

   # Kill active connections
   ss -K dst <DEST_IP>
   ```

2. **Process termination**
   ```bash
   # Find and kill suspicious processes
   lsof -i :<PORT> | grep <PID> | kill -9
   ```

#### Investigation
- Determine data classification of exfiltrated content
- Check for malware or backdoors
- Review user activity for past 30 days
- Identify initial compromise vector

---

### 3. Persistence Mechanism Created

**Alert Name:** `Persistence Mechanism Created`

#### Immediate Actions (0-5 minutes)
```bash
# 1. Identify the persistence type
splunk search "index=* host=<HOST> persistence_type=* | table _time, persistence_type, file_path, user"

# 2. Backup the artifact for forensics
cp <PERSISTENCE_FILE> /forensics/$(date +%Y%m%d)_<FILENAME>

# 3. Check for related activities
splunk search "host=<HOST> user=<USER> earliest=-24h | table _time, action, command"
```

#### Containment (5-15 minutes)
1. **Remove persistence**
   ```bash
   # For cron jobs
   crontab -u <USER> -r

   # For systemd services
   systemctl disable <SERVICE>
   systemctl stop <SERVICE>

   # For startup scripts
   rm /etc/rc.d/<SCRIPT>
   ```

2. **Monitor for recreation**
   - Enable file integrity monitoring
   - Set up real-time alerting

## High Priority Alert Response

### 1. Lateral Movement Detected

**Response Time:** Within 1 hour

#### Phase 1: Verification (0-15 minutes)
```bash
# Verify the movement pattern
splunk search "index=* src_host=<SOURCE> dest_host=<TARGET> | transaction user maxspan=1h"

# Check authentication methods used
splunk search "EventCode=4624 Logon_Type=* src_host=<SOURCE>"
```

#### Phase 2: Containment (15-30 minutes)
1. Disable network access between affected systems
2. Reset credentials for affected accounts
3. Enable enhanced authentication (MFA)

#### Phase 3: Investigation (30-60 minutes)
- Map the complete attack path
- Identify all compromised systems
- Check for data access or exfiltration

### 2. Privilege Escalation Detected

**Response Time:** Within 1 hour

#### Immediate Response
```bash
# 1. Identify escalation method
splunk search "index=* escalation_type=* host=<HOST> | table _time, user, escalation_type, command"

# 2. Check current privileges
id <USER>
groups <USER>

# 3. Review sudo logs
grep <USER> /var/log/sudo.log | tail -50
```

#### Containment Actions
1. Remove elevated privileges
2. Reset user password
3. Review and restrict sudo rules
4. Check for backdoor accounts

## Medium Priority Alert Response

### Failed Authentication Spike

**Response Time:** Within 4 hours

#### Analysis Steps
1. Determine if it's a brute force attack
2. Check source IP reputation
3. Identify targeted accounts
4. Review lockout policy effectiveness

#### Response Actions
```bash
# Temporary IP block if threshold exceeded
if [ $(grep -c <IP> /var/log/secure) -gt 100 ]; then
    iptables -A INPUT -s <IP> -j DROP -m comment --comment "Brute force block"
fi

# Enable account lockout
pam_tally2 --user=<USER> --reset
```

## Investigation Procedures

### Standard Investigation Workflow

1. **Initial Triage** (5 minutes)
   - Verify alert accuracy
   - Determine scope and impact
   - Assign incident priority

2. **Data Collection** (15 minutes)
   - Gather relevant logs
   - Capture system state
   - Document timeline

3. **Analysis** (30 minutes)
   - Correlate events
   - Identify attack patterns
   - Determine root cause

4. **Hypothesis Testing** (Variable)
   - Recreate attack scenario
   - Validate findings
   - Identify gaps

### Investigation Queries

```spl
# User behavior analysis
index=* user=<USER> earliest=-7d
| stats values(action) as actions,
        values(src_ip) as source_ips,
        dc(host) as unique_hosts,
        count by user
| where unique_hosts > 10

# Network traffic analysis
index=network src_ip=<IP> OR dest_ip=<IP>
| timechart span=1h sum(bytes_out) as outbound,
            sum(bytes_in) as inbound
| where outbound > 1073741824

# Process execution timeline
index=* EventCode=4688 OR type=EXECVE host=<HOST>
| eval process=coalesce(New_Process_Name, exe)
| timeline span=1m count by process
```

## Containment Strategies

### Network Isolation

#### Level 1: Partial Isolation
- Block specific ports/protocols
- Restrict external access
- Maintain internal connectivity

#### Level 2: Full Isolation
- Disconnect from network
- Use out-of-band management
- Preserve evidence

### Account Containment

1. **Immediate Actions**
   - Disable account
   - Force logout all sessions
   - Revoke all tokens/keys

2. **Investigation Phase**
   - Maintain read-only access
   - Monitor all activity
   - Preserve audit logs

### System Containment

```bash
# Create forensic snapshot
dd if=/dev/sda of=/forensics/disk_image.img bs=4M

# Isolate system
iptables -P INPUT DROP
iptables -P OUTPUT DROP
iptables -P FORWARD DROP

# Preserve volatile data
mkdir /forensics/$(date +%Y%m%d)
ps aux > /forensics/$(date +%Y%m%d)/processes.txt
netstat -antp > /forensics/$(date +%Y%m%d)/connections.txt
```

## Evidence Collection

### Critical Evidence Types

1. **System Logs**
   - Authentication logs
   - System logs
   - Application logs
   - Security logs

2. **Network Data**
   - Packet captures
   - Netflow data
   - Firewall logs
   - DNS queries

3. **System Artifacts**
   - Running processes
   - Network connections
   - File modifications
   - Registry changes

### Evidence Preservation

```bash
# Create evidence package
EVIDENCE_DIR="/forensics/INCIDENT_$(date +%Y%m%d_%H%M%S)"
mkdir -p $EVIDENCE_DIR

# Collect logs
tar -czf $EVIDENCE_DIR/logs.tar.gz /var/log/

# Collect system info
systeminfo > $EVIDENCE_DIR/systeminfo.txt
ps aux > $EVIDENCE_DIR/processes.txt
netstat -antp > $EVIDENCE_DIR/network.txt

# Create hash manifest
find $EVIDENCE_DIR -type f -exec sha256sum {} \; > $EVIDENCE_DIR/manifest.sha256
```

## Post-Incident Activities

### Immediate (Within 24 hours)

1. **Incident Report**
   - Timeline of events
   - Actions taken
   - Current status
   - Immediate recommendations

2. **System Hardening**
   - Apply emergency patches
   - Update security controls
   - Enhance monitoring

### Short-term (Within 1 week)

1. **Root Cause Analysis**
   - Identify initial vector
   - Map attack progression
   - Determine control failures

2. **Lessons Learned**
   - What worked well
   - What needs improvement
   - Action items

### Long-term (Within 1 month)

1. **Security Improvements**
   - Update security policies
   - Enhance detection rules
   - Improve response procedures

2. **Training and Awareness**
   - Update training materials
   - Conduct tabletop exercises
   - Share threat intelligence

### Post-Incident Checklist

- [ ] All compromised credentials reset
- [ ] Security patches applied
- [ ] Monitoring enhanced for affected systems
- [ ] Incident report completed
- [ ] Stakeholders notified
- [ ] Evidence properly preserved
- [ ] Playbook updated with lessons learned
- [ ] Follow-up monitoring active
- [ ] Vulnerability assessment completed
- [ ] Security controls validated
